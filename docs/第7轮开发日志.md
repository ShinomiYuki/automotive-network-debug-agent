# 第 7 轮开发日志：真实 CAN→LIN timeout 调查闭环与增量项目索引

## 1. 目标

本轮针对真实场景中 Channel 映射被猜测、CAN→LIN timeout 需要人工多轮配对、跨层链与反证不足、大型 generated source 输出爆炸、调查状态丢失，以及 Skill 可见但 MCP Tool 未注册等问题做最小完整改进。模型仍由 Codex / 兼容 Harness 提供，不创建或使用 `OPENAI_API_KEY`，不引入独立模型运行时。

## 2. Channel 与 BLF 时间语义

Trace Session 新增显式 Channel mapping。跨 Channel 工具只接受先由用户登记的 `analysis_channel`、`bus_type`、`logical_network`、`mapping_source` 与可选 `ecu_channel`；缺失、重复冲突或未登记都会返回业务错误，配置顺序和命名不参与推断。

BLF 摘要现在返回 FileStatistics 元数据及 `timestamp_reference`。时间由 measurement start 与 object header offset/分辨率计算，时钟域标记为 BLF logger；采集点与 ECU 内部发送时刻没有元数据时明确为 `UNKNOWN`。

## 3. CAN→LIN timeout 一次性关联

`analyze_routed_signal_timeout` 一次接收源 CAN Channel/Message、多个目标 LIN Channel/Frame、信号、timeout 值与配置超时。结果按源停止事件给出最后源帧、目标旧值、首个 timeout 值、延迟、目标周期与错过的真实总线帧数；每个 LIN Channel 独立汇总 min/P50/P95/max，并只返回有界异常原始帧。该 Tool 只证明日志时序，不判断 Com/PduR/LinIf/CDD 或硬件根因。

## 4. SQLite 项目索引与大文件模式

Config 首次加载先建立一次文件清单，再把 C/C++ 符号、宏/配置标识符、绝对路径、模块、generated 标记、行号、列号和行 byte offset 写入用户缓存目录下的 SQLite。默认目录位于本机用户应用缓存，可用 `ANDA_CACHE_DIR` 或 Load Tool 的 `cache_directory` 覆盖；缓存不进入工程和 Git。

索引以绝对路径、文件大小和 `mtime_ns` 增量失效，仅重建变化文件。基础索引更新后会生成内容代的不可变 generation，当前 Workspace 始终查询该 generation，避免其他 MCP 进程后续更新时将新源码与旧 ARXML 混用。referable-key 汇总注释不进入 occurrence 索引；超长 generated 行默认返回 500–1000 字符局部窗口、数组/表名及解析字段，零上下文。`read_source_lines` 通过已记录 byte offset 一次读取多个明确行范围。

`plan_source_search` 先按问题类型选择 CanIf/Com/PduR/LinIf/OS-RTE/BswM/ComM/CDD 等阶段和候选文件；`search_source_evidence` 批量查询最多 50 个标识符，并为未命中结果保留模块、source/generated 过滤和排除目录范围。

## 5. 跨层链与反证

`trace_autosar_runtime_chain` 组合已加载 ARXML 与源码索引，输出生产者/消费者、buffered/unbuffered、deferred/immediate、任务周期/优先级、callout/CDD 插入点、I-PDU Group、schedule 控制者和逐层文件/行号。所有无法由显式配置或源码证明的字段保留 `UNKNOWN`，`runtime_order_inferred=false`、`root_cause_inferred=false`。

结果同时带 `counter_evidence`：每个候选明确为 FOUND、NOT_FOUND_IN_SCOPE 或 UNKNOWN，并携带搜索范围和“不能排除间接调用/未加载代码”的边界。

## 6. 调查状态与报告

Config MCP 新增 investigation bundle：在用户明确输出目录创建 `case.json`、六类 `evidence/*.json`、`hypotheses.json` 和 `open_questions.json`；随后可追加证据、替换假设/开放问题、读取有界摘要并确定性导出 `report.md`。写 Tool 标注为非破坏但非幂等，读 Tool 保持只读。当前支持 JSON/Markdown，PDF 后端明确返回 unavailable。

## 7. 健康检查与可见进度

两个 MCP 各自提供健康 Tool，区分“当前 MCP 已实际响应”和“另一个 MCP 只在插件清单中配置”。结果包含 Trace/Config、BLF parser、DBC/LDF decoder、ARXML parser、SQLite 项目索引和报告导出能力；当 Skill 已加载但 Tool 不存在时，Skill 要求在大文件工作前停止并检查安装缓存、MCP 注册/启动错误，再新建会话。

Trace 与 Config 后台状态继续返回 stage、计数、百分比与耗时。Skill 在冷索引超过约 5 秒时据此给出简短进度，不重复 Load。

## 8. 缓存边界

- Config 源码清单、occurrence 和行偏移跨 MCP 进程持久化；ARXML 对象在当前 Config Workspace 中复用。
- BLF 紧凑帧索引与 DBC/LDF 定义在当前 Trace Session 中分别复用，避免同一调查重复解析；本轮没有把大型 BLF payload 再复制到磁盘。
- HTML/测试报告可进入 investigation bundle 作为用户提供证据，但当前没有专用 HTML 解析器；健康/Skill 会明确该边界，不以宽泛文本搜索冒充结构化解析。

## 9. 验证范围

新增确定性测试覆盖显式 Channel mapping、双 LIN Channel timeout 统计、异常原始帧、BLF 时间语义、SQLite 增量复用、文件清单规划、批量有界源码证据、byte-offset 行读取、referable-key 排除、限定范围负向搜索、跨层链与反证、健康检查及 investigation bundle 往返导出。Harness eval 规格新增 CAN→LIN timeout、大型 generated source、跨层链和带报告的联合调查路径。
